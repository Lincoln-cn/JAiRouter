JAiRouter · Release Plan

v3.2.0 — PII 治理与配额操作闭环
（TDD 驱动交付）

在 v3.1.x 配额账本与多协议入口之上，补齐「聊天日志/调用历史 PII 可管理」与「API Key 配额操作闭环」， 并建立前端三层测试（单元 / 接口 / 页面）。全过程采用红→绿→重构：先写测试，再写实现，最后跑通验证。

策略 TDD 基线 v3.1.2 目标 v3.2.0 minor 主战场 聊天记录 / 用户数据 / 配额 Key 限额

1背景与目标

问题回顾

  • 配额：限额在 API Key 表单，Quota 页只管账本全局开关，监控页缺限额对照，操作链路不直观
  • PII：原先仅有 YAML + 半成品服务层，无 Web 管理；SUMMARY 记录脱敏受网关开关拖累
  • 排除路径：过滤器原意 vs 配置列表相反（AI 被排除、管理台未排除）
  • Flaky：Redis TTL 秒精度断言写死 N+1

v3.2.0 交付目标

  • 记录侧脱敏 sanitizeForStorage 与网关开关解耦，SUMMARY 链路独立生效
  • PII 管理闭环：配置热改 / 规则列表 / 试脱敏 + 控制台页
  • 排除路径对齐：管理台 /api/** 与 AI 实时路径均排除网关响应脱敏
  • 配额监控：限额对照 + 进度 + 与 API Key 页交叉链接
  • 前端测试地基：vitest 单元 + 接口契约 + Playwright 页面冒烟

2版本切分

版本 范围 类型 状态
v3.1.3 TTL flaky 修复、文档口径（0=不限制 / threshold 0–1）、排除路径对齐补丁可随 v3.2.0 一并合入主分支 patch 已落地
v3.2.0 PII 管理 API + 控制台页 + sanitizeForStorage + 配额观测闭环 + 测试地基 + 权限码 security:sanitization:manage minor 推进中
v3.2.1+ 规则持久化 StoreManager 版本化、PII 试脱敏回归集、配额 HOUR/MONTH 限额扩展、记录级 FULL 加密策略 UI 后续 待规划

3工作流与 TDD 纪律

统一循环

Red 写失败测试 → Green 最小实现 → Refactor 清理 → API 接口契约 → Page 页面冒烟
前端覆盖约定： 单元测试（vitest + @vue/test-utils）覆盖表单/工具函数； 接口测试覆盖 /api/config/sanitization/** 与配额观测响应契约； 页面测试（Playwright）覆盖：登录 → 菜单可见性 → PII 页保存/试脱敏 → 配额监控限额列。

4工作流拆解（WS）

WS-1 测试地基

  • frontend 增加 vitest / @vue/test-utils / happy-dom
  • npm run test:unit / test:api 脚本
  • Playwright 冒烟脚本模板（.mimocode/pw）

WS-2 后端 PII 核心

  • sanitizeForStorage 单测（开关关闭仍生效）
  • rebuildRulesFromProperties 热重建
  • Controller 单测 + 权限规则闭包

WS-3 排除路径边界

  • ExcludedPathsConfigTest
  • Filter 测试：管理台 / AI 路径跳过
  • javadoc 与设计裁决一致

WS-4 控制台 PII 页

  • API client 单测（mock request）
  • 组件测试：表单同步/保存 payload
  • 页面：菜单、权限、试脱敏 UI

WS-5 配额操作闭环

  • 监控页限额对照逻辑单测
  • API Key ↔ 监控交叉链接
  • 文档操作闭环表

WS-6 发布验收

  • 后端相关测试全绿
  • vue-tsc + 构建通过
  • changelog / 权限码 49
