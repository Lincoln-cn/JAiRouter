本手册面向首次使用 JAiRouter Web 控制台的操作者，覆盖从登录到首次接通模型服务、配额管理、观测排查、权限控制的完整动线。

## 1. 登录与首次启动

### 1.1 访问地址

| 部署方式 | 地址 | 说明 |
|----------|------|------|
| 本地开发（Vite） | `http://localhost:3000/admin` | Vite dev server，热更新 |
| 生产/独立部署 | `http://<host>:8080/admin` | 后端直接托管 SPA |

两个入口指向同一套前端代码，功能完全一致。

### 1.2 默认账号

| 用户名 | 默认密码 | 角色 | 说明 |
|--------|----------|------|------|
| `admin` | `ChangeMeOnFirstStartup123456` | ADMIN, USER | 超级管理员，拥有全部 79 个权限码 |
| `user` | `user123456` | USER | 普通用户，只读为主 |

> ⚠️ **首次部署务必修改 `admin` 密码**。密码通过环境变量 `INITIAL_ADMIN_PASSWORD` 设置（见 `src/main/resources/config/auth/jwt.yml`），修改后重启服务即生效。

```bash
# 示例：启动前设置环境变量
export INITIAL_ADMIN_PASSWORD="YourStr0ngPassword#2026"
```

### 1.3 Token 存储

登录成功后，JWT 存储于浏览器 `localStorage`，键名为 `admin_token`。

> ⚠️ **不建议手动注入 token**。前端路由守卫（`router.beforeEach`）在每次导航时会：
>
> 1. 检查 `localStorage` 中是否存在 `admin_token`；
> 2. 解码 JWT 检查是否过期（提前 60 秒判定过期）；
> 3. 校验路由 `meta.roles` / `meta.permissions` 是否满足。
>
> 仅满足全部条件才放行，否则重定向到 `/login`。手动写入的 token 如果过期或缺失 `permissions` claim，控制台将无法正常使用。

### 1.4 登录流程

1. 在浏览器打开控制台地址；
2. 页面标题显示「**JAiRouter 管理后台**」（英文：**JAiRouter Admin**）；
3. 输入用户名和密码，点击「**登录**」（**Login**）按钮；
4. 登录成功后自动跳转到「**仪表板**」（**Dashboard**）页面。

![登录页面](images/login-zh-CN.png)

## 3. 首次接通一个模型服务的最小动线

以下步骤按照依赖顺序，以配置一个 Ollama 模型服务为例。

![服务管理页](images/service-management-zh-CN.png)

### 步骤 1：配置服务

**菜单路径**：模型与实例 → 服务管理

1. 进入「**服务管理**」页面；
2. 点击「**添加服务**」（**Add Service**）按钮；
3. 填写表单：

| 字段 | 说明 | 必填 |
|------|------|:----:|
| 服务类型（Service Type） | 下拉选择，如 `chat`、`embedding`、`completion` 等 | ✅ |
| 适配器（Adapter） | 下拉选择适配器类型 | ✅ |
| 负载均衡策略（Load Balance Strategy） | 八种：轮询 / 加权 / 最少连接 / IP 哈希 / 一致性哈希 / EWMA 延迟感知 / 随机 / 会话粘性 | ✅ |
| 说明（Description） | 可选备注 | ❌ |

4. 点击「**保存**」（**Save**）；
5. 保存成功后，服务类型出现在列表中，状态为「**已启用**」（**Enabled**）。

### 步骤 2：配置实例

**菜单路径**：模型与实例 → 实例管理

![实例管理页](images/instance-management-zh-CN.png)

1. 进入「**实例管理**」页面；
2. 选择对应的服务类型（左侧下拉）；
3. 点击「**添加实例**」（**Add Instance**）按钮；
4. 填写表单：

| 字段 | 说明 | 必填 | 示例 |
|------|------|:----:|------|
| 服务类型（Service Type） | 关联的服务类型 | ✅ | `chat` |
| 实例名称（Instance Name） | 实例标识 | ✅ | `ollama-local` |
| 基础URL（Base URL） | 下游服务地址 | ✅ | `http://localhost:11434` |
| 路径（Path） | 请求路径（可选） | ❌ | `/v1/chat/completions` |
| 权重（Weight） | 负载均衡权重 | ✅ | `1` |
| 适配器（Adapter） | 留空使用全局配置 | ❌ | — |

5. 展开「**请求头配置**」（**Request Header Config**），添加下游所需认证头：

| 头名称 | 头值 | 说明 |
|--------|------|------|
| `Authorization` | `Bearer <your-api-key>` | 透传给下游模型服务的认证凭据 |

> 💡 `Authorization` 头是**透传给下游服务**的，不是网关自身的凭据。网关凭据为 `X-Jairouter-Token`（JWT）。

6. 可选：展开「**标签配置**」（**Tag Config**），添加标签用于路由规则筛选；
7. 点击「**保存**」（**Save**）；
8. 保存成功后，实例出现在列表中，状态列显示健康状态（健康/异常）。

### 步骤 3：版本与 Adapter（如需）

- **版本管理**（模型与实例 → 版本管理）：如果模型服务需要指定版本信息，可在此配置。非必须步骤。
- **Adapter管理**（模型与实例 → Adapter管理）：查看和管理已注册的适配器。如果步骤 1 中已正确选择适配器，此步可跳过。

### 步骤 4：验证连通性

配置完成后，可通过以下方式验证：

1. **仪表板**（概览 → 仪表板）：查看「服务配置速览」区域，确认服务实例数量、健康实例数是否正确；
2. **实例管理**页面：实例状态列应显示绿色「**健康**」标签（非「**异常**」）；
3. **负载均衡监控**（流量治理 → 负载均衡监控）：查看实时负载均衡状态。

### 步骤 5：在 Playground 试调用

**菜单路径**：开发工具 → AI 试验场 → 对话测试

1. 进入「**对话测试**」（**Chat Playground**）页面；
2. 选择模型（Model）为步骤 1 中配置的服务类型对应的模型；
3. 输入消息并发送；
4. 如果收到回复，说明整个链路（控制台 → 网关 → 模型服务）已打通。

> 💡 Playground 需要 `ai:playground:use` 权限码。ADMIN 和 USER 角色默认拥有此权限。

## 4. 配额怎么用

### 4.1 配额运行时配置

**菜单路径**：平台设置 → 运行时配置 → 配额运行时配置

配额功能**默认关闭**。要启用配额：

![配额运行时配置页](images/quota-config-zh-CN.png)

1. 进入「**配额运行时配置**」页面；
2. 找到「**热编辑配置**」（Hot-Editable Configuration）区域；
3. 打开「**启用配额**」（Enable Quota）开关；
4. 可选配置：
   - **降级放行**（Fail Open）：配额系统异常时是否放行请求；
   - **统计窗口**（Stat Windows）：选择统计维度；
5. 点击「**保存配置**」（Save Configuration）；

**可热改的字段**（无需重启）：

| 字段 | 说明 |
|------|------|
| `enabled` | 启用/禁用配额 |
| `failOpen` | 降级放行开关 |
| `windows` | 统计窗口选择 |

**需重启生效的字段**（标记「**需重启**」徽标，只读）：

| 字段 | 说明 |
|------|------|
| `backendName` | 存储后端名称 |
| `distributedEnabled` | 分布式启用 |
| `distributedKeyPrefix` | 分布式 Key 前缀 |
| `distributedTimeout` | 分布式超时 |
| `flushIntervalSeconds` | 刷新间隔 |

### 4.2 配额用量监控

**菜单路径**：运行观测 → 用量统计 → 配额使用

进入「**配额用量监控**」页面可以：

- 查看配额**运行状态**：存储后端类型、降级状态；
- 按**租户 ID / API Key ID / 用户 ID / 服务类型 / 模型 / 统计窗口**筛选用量数据；
- 查看**用量明细**：请求数、Token 数。

> 💡 如果页面显示「**配额账本未启用，用量数据暂不可用**」，说明配额功能未开启，需先到「配额运行时配置」页面启用。

## 6. 权限与角色

### 6.1 七个内置角色

| 角色 | 权限码数 | 权限范围 | 说明 |
|------|:-------:|----------|------|
| **ADMIN** | 79 | 全量权限码 | 超级管理员；URL 规则直通，JWT 内嵌全量码 |
| **OPERATOR** | 55 | 全部 `:read` + `:write` 码 | 日常运维；不含系统管理（`system:*`）、安全管理类 `manage`（API Key / JWT 令牌 / 黑名单管理）；含 `callhistory:read`（可看调用记录与摘要，看不到正文） |
| **USER** | 9 | 本人调用记录、本人异常、本人 Token 用量、慢请求、链路搜索、LB/CB/RL 监控、AI 试验场 | 普通用户；全部为读码，不含任何写码与全局观测码（`monitoring:tokenusage:read`、`monitoring:exceptions:read` 已从存量库回收） |
| **VIEWER** | 31 | 全部 `:read` 码（排除与写/管理面配对的 10 个码与 `callhistory:read`） | 纯只读角色；不含调用历史（`callhistory:read`）、`ai:playground:use` |
| **AUDITOR** | 3 | 概览仪表板、安全审计事件、管理操作记录 | 第三方审计最小集；严格只读，刻意不含调用记录明细（业务数据）、任何 `config:*:read` 与写码 |
| **SLA_READONLY** | 35 | 只读巡检面 | 给 SLA 工具用的只读角色：仪表板、config 只读、lb/cb/rl 监控、`callhistory:read`（仅摘要）、monitoring 只读、tracing 只读、审计日志只读；不含正文与任何管理码 |
| **SLA_OPERATOR** | 53 | 只读巡检面 + 配置写 | 在 SLA_READONLY 之上加 15 个 `config:*:write`、`lb:config:write`、`tracing:config:manage`、`monitoring:config:write`；仍不含账户/权限管理与 `security:*:manage` |

### 6.2 为什么看不到某些菜单页 {#why-menu-pages-missing}

前端菜单渲染基于权限码过滤：

1. 每个菜单组/菜单项关联一个权限码（如 `config:services:read`）；
2. 登录后 JWT 的 `permissions` claim 包含当前用户的权限码列表；
3. `usePermission` 组合式函数在渲染时过滤掉用户不拥有的菜单项；
4. 路由守卫（`meta.permissions`）进一步拦截无权限的直接 URL 访问。

**解决方式**：

1. **系统** → **权限管理**页面（需 `system:permissions:manage` 权限，仅 ADMIN）；
2. 找到目标角色，勾选缺失的权限码并保存。

> 💡 `/v1/**`（OpenAI 兼容推理端点）独立于 RBAC 体系，仅要求认证，不受权限码限制。

## 8. 常见问题

### 8.1 登录后页面显示 401

**现象**：登录后 API 请求返回 401 Unauthorized。

**可能原因**：

1. JWT 已过期（默认有效期 60 分钟）；
2. 环境变量 `JWT_SECRET` 与部署时不一致，导致 token 验签失败。

**处理**：

- 重新登录获取新 token；
- 确认 `JWT_SECRET` 环境变量在重启后未改变。

### 8.2 登录后页面显示 403

**现象**：部分 API 返回 403 Forbidden。

**可能原因**：当前用户角色缺少对应权限码。

**处理**：

- 用 `admin` 账号登录，进入「访问与身份 → 权限管理」为对应角色补充权限码；
- 参考 [RBAC 权限管理](../security/rbac-permissions.md) 文档了解权限码体系。

### 8.3 看不到某些菜单页

**现象**：登录后侧边栏缺少部分菜单分组或页面。

**可能原因**：当前用户角色不包含对应菜单项的权限码。

**处理**：

- 参见本文「[6.2 为什么看不到某些菜单页](#why-menu-pages-missing)」一节。

### 8.4 OpenAI SDK 接入报错

**现象**：使用 OpenAI SDK 调用时返回 401。

**可能原因**：SDK 默认使用 `X-Jairouter-Token: <key>` 头，而非 `X-API-Key`。网关的 OpenAI 兼容端点要求 `X-API-Key` 头携带 API Key。

**处理**：

- 使用 `X-API-Key` 头而非 `Authorization` 头传递 API Key；
- 参考「开发工具 → 客户端接入指南」页面的 SDK 示例。

### 8.5 Redis 不可用时的降级提示

**现象**：仪表板或监控页面提示连接异常。

**可能原因**：JAiRouter 依赖 Redis 进行 JWT 持久化/配额分布式存储时，Redis 未启动或不可达。本地开发环境默认 Redis 关闭（`redis.enabled: false`），JWT 使用 H2 + 内存回退。

**处理**：

- 本地开发：无需 Redis，JWT 使用 H2 存储 + 内存回退，功能不受影响；
- 生产环境：确保 Redis 可用，或配置 `jairouter.security.jwt.persistence.fallback-storage: memory`。

### 8.6 配额不生效

**现象**：发送请求后配额用量监控页面无数据。

**可能原因**：配额功能默认关闭。

**处理**：

1. 进入「流量治理 → 配额运行时配置」；
2. 启用配额开关并保存；
3. 确认存储后端状态正常（非降级）。

## 9. 页面导览与读法

README 只保留四组主截图（指挥中心、服务与实例、观测与记录、演练场与接入）。这一节承接逐页说明：每一页在回答什么问题，以及读它的数字时容易误解的地方。

### 9.1 服务管理：三元组与四步引导

一个服务 = （服务类型、适配器、负载均衡策略）。网关能提供七种服务类型 —— 对话、向量化、重排、语音转文字、文字转语音、图像生成、图像编辑 —— 各自绑定一个适配器（GPUStack、vLLM、Ollama、OpenAI……）与一套均衡策略（八种，见 3. 步骤 1 的字段表）。

页面顶部的四步引导是接新后端的推荐顺序：配置适配器 → 创建服务 → 添加实例 → 去演练场试一次。适配器配错会在第一步就暴露，而不是等第一个真实请求打进来。

### 9.2 实例管理：真实端点与单实例控制

一个实例就是一个真实端点：Base URL、路径、权重、单实例请求头与标签，按服务类型分页签。权重供加权类策略使用，标签供规则条件使用，单实例请求头则是让下游凭据只留在那一个上游的写法。

每一行实例自带限流与断路器 —— 某个上游出问题时可以只隔离它、只修它，不用动整个服务。

### 9.3 路由规则：先于均衡，停用不删

规则在任何负载均衡决策之前生效，按优先级排序，可拖拽调整顺序。一条规则可以停用而不必删除，命中计数实时更新 —— 所以一条从不命中的规则是看得见的，不会悄悄变成死配置。租户固定、灰度分流、按请求头 A/B 这些常见形态有模板可直接套用。

### 9.4 调用历史看板：三档记录收敛成一个看板

每次调用按三档之一记录（仅元数据 / 脱敏摘要 / AES-256-GCM 加密全文，切换见「安全 → 记录治理」）。看板把记录收敛成运维真正要看的数：总请求与失败请求、成功率、平均响应时间、Token 消耗与单请求均值，再往下是每日趋势、Top 10 模型、服务类型构成与 24 小时分布。顶部的时间范围会一次性筛掉所有面板，原始记录就在旁边的页签里。

### 9.5 慢查询：告警「触发」与「抑制」各是什么

慢查询会被计数、按操作类型归类，并给出每组的次数、平均、最大、最小与总耗时，另有一张热点表指向最差的那几个。右侧两个数字容易读错：告警**触发**次数与告警**抑制**次数。抑制走的是冷却逻辑 —— 同一个热点持续越过阈值只记一次，之后安静下来，所以「抑制多、触发少」说明冷却在工作，而不是阈值坏了。

### 9.6 配额运行时配置：热改 vs 需重启

配额设置按「生效代价」分成两类：**可热改**的（启用配额、降级放行、统计窗口）保存即生效；**需重启**的字段是只读的、带角标说明，而不是让人改完才发现没生效。页面顶部的状态条会摊开当前实际状态：启用还是关闭、存储后端（本地或 Redis）、是否降级放行、刷写间隔。配额默认关闭，这里就是打开它的地方。

### 9.7 配额用量监控：六个维度与四张状态卡

用量可以同时按六个维度筛 —— 租户、API Key、用户、服务类型、模型、统计窗口 —— 按租户对账或按 Key 复盘事故都不必先导出数据。

上方四张状态卡先回答出事时真正该问的问题（账本是否启用、用的是哪个后端、是否降级、有几个活跃窗口），再展示数字；没有数据时直接说明原因（配额账本未启用），而不是渲染一张空表让人猜。

### 9.8 客户端接入指引

给外部团队的第一页：Base URL、`X-API-Key` 请求头、`GET /v1/models`、`POST /v1/chat/completions` 及其流式写法，然后是同一段调用的 `curl` 版本与 OpenAI Python SDK 版本，每个块都有复制按钮。Base URL 取自这台网关自己的配置，所以复制到的就是它实际对外提供的地址。

### 9.9 演练场

一个模型选择器后面挂了五个测试台：对话、向量化、重排、语音服务与图像服务。凭据、路由与记录治理都和真实客户端一致，但请求与流式响应直接显示在页面上 —— 验证一个新加入的实例能不能正确应答，这是最快的路径。没选模型之前发送是禁用的，不会出现「点了没反应」。

### 9.10 主题与语言

顶栏一个开关就能切到暗色主题，不需要另起构建，也不用加查询参数；zh-CN / en-US 切换就在它旁边。两者都只影响控制台显示，不改变任何接口行为。

### PII 脱敏管理（v3.2.0）

路径：**安全 → PII 脱敏管理** `/security/sanitization`（权限 `security:sanitization:manage`）

操作动线：
1. 查看响应侧子配置（PII 正则、敏感词、掩码字符、生效范围）
2. 热改后点保存（同步重建规则库，记录侧 SUMMARY 立即生效）
3. 「试脱敏」粘贴聊天样例，确认脱敏后出现 `****`
4. 说明：网关实时响应默认不脱敏；管理台 `/api/**` 与 AI 路径已排除

### 记录治理（v3.5.1）

路径：**安全 → 记录治理** `/security/record-governance`（权限 `config:callhistory:read` / `config:callhistory:write`）

操作动线：
1. 「记录级别」三档单选：`METADATA_ONLY`（仅元数据）/ `SUMMARY`（摘要）/ `FULL`（完整内容，加密落库）；切到 `FULL` 会二次确认
2. 「加密与存储」只读区同时显示**配置请求的密钥来源**与**实际生效的密钥来源**，以及密钥指纹、单条内容上限（默认 64 KB）、保留期与最大记录数
3. 若配置请求 `env` 但环境变量 `JAIR_CALL_HISTORY_KEY` 不可用，页面顶部出现回退警告，且「实际生效」显示 `auto` —— 此时内容用的是 `~/.jairouter/call-history.key` 文件密钥
4. 保存只提交 `recordLevel`，其余字段由 `jairouter.call-history.*` 配置决定，页面不可改
5. 在 `FULL` 级别下查看单条调用详情会触发服务端解密，并写入 `FULL_CONTENT_ACCESS` 审计（可在「审计日志」页查询）

### API 密钥配额操作（v3.2.0）

路径：**安全 → API 密钥** 列表操作列 **「配额」**

操作动线：
1. 打开配额抽屉：今日用量 / 剩余量 + 预设（不限制/开发/标准/严格）
2. 调整限额后「保存配额」（只改配额字段，不改密钥其它属性）
3. 「重置计数」清零当日请求/Token 与速率
4. 配额监控页可交叉跳转到 API Key 设置限额
